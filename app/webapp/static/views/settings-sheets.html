            Setup, in order

            1. In @BotFather send /newbot to create one bot per profile and copy each token (for a group chat also send /setprivacy and choose Disable). A bot token allows only one listener, so two sessions on one bot fight — never share one.
            2. Install the plugin once in the life-os project: /plugin install telegram@claude-plugins-official. It needs Bun on your PATH (bun --version should print a number); the checks above show both.
            3. Give each bot its own folder — ~/.claude/channels/telegram-<id> — and put its token there yourself: create a file named exactly .env in it with one line, TELEGRAM_BOT_TOKEN=<token>. Edit it in an editor, not in a chat — the launcher never reads it. In Notepad pick Save as type: All files, or it saves .env.txt and the plugin never sees it.
            4. Copy config/channel_profiles.sample.json to config/channel_profiles.json (machine-local, gitignored) and list each profile: id (a lowercase slug), label, skill (lowercase, exactly one of the chips above) and state_dir (the folder from step 3 as an absolute path that exists, with forward slashes; two profiles may not share one). It holds names and paths only, never a token. Re-check below says what each row still needs.
            5. Make sure nothing else claims the token. An ambient TELEGRAM_BOT_TOKEN beats every profile's .env: if one is set in Claude's env block (~/.claude/settings.json) or in the system environment, every profile listens on that one bot and yours never answers. Remove it there and keep it where its own tool reads it (fleet hooks read fleet-config's gitignored .env). Then give the plugin's default folder, ~/.claude/channels/telegram/.env, a token of a bot no profile uses: an ordinary life-os session starts the plugin too, and a failed start is remembered for about 15 minutes, during which profile sessions skip the plugin.
            6. Tap Re-check (every row should read Ready), then on the Life tab open the menu of the profile's skill and tap Start on Telegram. Then DM the bot itself, not a group: it replies with a 6-character code, good for 1 hour. In that profile's terminal run /telegram:access pair <code>; the bot answers “Paired!”. Pairing is per person, not per chat: each extra person (say, your wife) DMs the bot themselves and you pair their code in the same terminal. Everyone paired shares that one session and its context. The policy stays pairing, so a stranger only ever gets a code you can ignore; a group is ignored until you add it with /telegram:access group add <group id>.

            If the bot doesn't answer

            • No reply to /start or a message. The plugin isn't listening to this bot. In the profile's folder, no bot.pid means the plugin never started with it (see the next point); a bot.pid and still silence means another token overrides it (step 5).
            • “failed to connect” or “Skipping connection (recent failure cached…)” at session start. Claude remembers a failed plugin start for about 15 minutes. Wait it out, then stop and start the profile; the default-folder token in step 5 stops it recurring.
            • Paired, but no “Paired!” message. An approved/<your id> file left in the folder means the plugin server isn't running; fix the start above and the message goes out within seconds.
            • No code arrives. You messaged a group instead of the bot's own chat, or it already sent the code twice (it then goes quiet; the code lasts an hour).
