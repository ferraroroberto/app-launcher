Count only chief-dispatched sessions

On, the cap counts only the sessions the chief started, so the ones you open yourself never use up a slot. Off, it counts every live session. The chief itself and Telegram channel sessions never count.

Automations

Everything the chief does on its own. Each switch saves when you tap it, and no restart is needed.

Doorbell

Wakes the idle chief within seconds when its mailbox has worker news, by typing one fixed line into its terminal. It never types while the chief is busy or you have a message half-typed. Off, only the fallback check below wakes it.

A backup for the doorbell, on even when the doorbell is off. Every this many minutes the launcher wakes the chief once if a mailbox event has waited that long, or a worker slot is free while plan items are queued. It follows the doorbell's rules, except that an input line that stays unreadable that long no longer holds it back. 0 turns it off.

Auto-drain queue

The chief adds unattended audit fixes to its plan and starts one whenever a worker slot frees. Off, those issues wait until you ask for them.

Auto-compact

The chief compacts its own conversation when its context use reaches this share, from 10 to 90%. Off, it never compacts on its own.

Grok for Sonnet lanes

A Board start asking for Sonnet runs on Grok Build instead when Claude's weekly use is within 5 points of the week's pace or above it. Opus lanes never switch. An unknown Claude reading, Grok not installed, or a repo Grok has not trusted (run grok --trust once in it) keeps the lane on Claude.

Job failures

Leaves the chief a mailbox event when a Job run fails, while a chief is running. Off, a failed run only notifies you.

CI failures

Leaves the chief a mailbox event when a GitHub CI run fails on a repo's main branch, while a chief is running. Off, CI shows only on the Board.

Job self-heal

Lets the chief try to repair a Job that failed, instead of only being told. Off, a failed run is reported and nothing is repaired on its own.

Weekly proposals

Lets the chief draft its weekly proposals without being asked. Off, it proposes nothing until you ask.

Grok Bot

Lets the Grok Bot ensure Job keep it running and lets its relay send. Off, the Job does nothing, the digest says disabled and the relay refuses to send; reads still work.

Grok Bot directive

The directive Grok Bot runs from, read live from the fleet. Copy it into Grok Bot when its updated time is newer than your pasted copy.

Timings

How long the chief's helpers wait. Each saves when you leave the field, and the defaults are the values the chief has always used. The re-ring and re-offer times apply at once; the hold and stall times apply once the chief's own tools read them.

After the doorbell rings, it waits this long. If the chief is still idle with mail waiting, the ring did not land, so it rings again. 30 to 600, default 60.

Mail the chief took but never finished is offered again after this long, because whatever took it is assumed gone. Keep it longer than a busy chief turn. 10 to 120, default 15.

When the chief tries to stop while it should compact, or while worker slots sit free beside queued work, it is held back at most once in this window, so a hold can never loop. 5 to 60, default 10.

An unattended run that prints nothing for this long is stopped as stuck. Long enough for a slow test run. 15 to 240, default 45.

How the chief works

Fixed safety rules. They are shown here so you know what to expect, and cannot be changed.

  • The doorbell looks every 3 seconds and rings only after the reason has held for 3 seconds, so workers that finish together cause one ring.
  • It types only into a chief idle at its prompt with nothing half-typed, and its line carries no data. A chief that says it is working but has printed nothing for 10 minutes counts as idle.
  • The fallback check looks every 30 seconds.
  • A message sent to a worker is resent only when its conversation shows it never arrived, and never after every send failed, because a repeated message could run a merge twice.
  • One live session per repo. The chief itself never counts against the worker cap (1 to 10).
  • A yolo start needs an explicit confirmation.
  • One session per Telegram bot.
  • A chief restart waits up to 8 seconds for the old chief to quit, so two chiefs never run.
  • The chief compacts itself only when its handover notes and plan were written in the last 10 minutes, so nothing is lost.
  • Mail older than 24 hours is dropped. A worker start still pending after 30 minutes shows as stalled on the Board.
  • Resume offers a chief conversation up to 7 days old.
