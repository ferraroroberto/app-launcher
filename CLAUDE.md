# Project Instructions

## This repository
Phone-first launcher hub for the rest of the home stack. Six tabs: **Coding**, **Apps**, **Jobs**, **Life OS**, **Board** (fleet kanban, incl. the dispatch bar's chat mode talking to a standing fleet chief), and **Settings**. Sister project to `photo-ocr` and `voice-transcriber` (same conventions, auth model, Cloudflare tunnel pattern). Setup, layout, and tab-by-tab usage: `README.md`.

**Adding a coding agent?** Follow `fleet-config`'s [`docs/adding-a-coding-harness.md`](https://github.com/ferraroroberto/fleet-config/blob/main/docs/adding-a-coding-harness.md) (fleet-config#491) — both halves in dependency order: the `fleet-config` side (context file, skills, hooks, Board state, model tiers), then this repo's (`src/agents.py` entry, brand icon, flag builder, launch-router dispatch, README). Probe per-harness facts, never assume them; don't re-derive the procedure from a prior agent's diff.

**Project specifics:**

- **Stack:** FastAPI + vanilla JS — **not** Streamlit; do not introduce Streamlit.
- **Config & secrets:** no `.env`. Project config in `config/config.json` (committed template only); runtime UI prefs + secrets in `config/webapp_config.json` (gitignored).
- **Registries:** apps in `config/apps.json` (gitignored, committed sample `config/apps.sample.json`), every row carrying a `kind` — `streamlit` | `webapp` | `tunnel` | `tray` — which back the **Apps** tab; jobs in `config/jobs.json`. **Coding** and **Life OS** need no registry (they list directories live).
- **Verification — the pre-ship gate is `pwsh -File scripts/verify-before-ship.ps1`** (boots its own disposable webapp + session-host, no tray needed); run it before declaring any webapp/launcher/session-host change done. Detail: README "Playwright smoke + regression tests" and "Verifying changes before ship".
  - Dev loop with the tray up: `.\scripts\run-e2e.ps1` (both projections) or `--browser chromium` for a faster pass. Targeting the live `:8445` tray is an explicit opt-in (#386) — the script sets `LAUNCHER_E2E_LIVE=1`; a bare `pytest tests/e2e` without it (and without `LAUNCHER_E2E_AUTOBOOT=1`) exits with a guard message. Never point ad-hoc pytest runs at the live webapp the phone is using.
  - Suite = `tests/e2e/test_smoke.py` plus one regression test per closed iPhone bite; `tests/e2e/` is its own index — don't re-enumerate the closed bites here. Byte-loss at the PTY write boundary has a non-browser real-PTY guard, `tests/test_session_host_pty_realpty.py` (in the `not smoke` suite). Non-browser suite alone: `pytest tests -m "not smoke" -v`.
  - **Modal contract (#545, supersedes #484): a dialog has a header ✕ close plus one full-width primary action** — new dialogs follow this shape.
  - **The e2e phase is diff-proportionate (#568):** byte-compile + the non-e2e pytest suite always run, but the *browser* slice is routed by `scripts/classify_e2e.py` against `main` — a static-asset-only diff runs Chromium-only smoke (~15s), a backend/docs-only diff runs no browser suite, and any `.js`/`.css`/real-page/session-host/e2e-test change (or any mixed/ambiguous/unrecognized diff) runs the full dual-projection suite. Routing is fail-safe: uncertainty always escalates to full, never narrows; the chosen tier + triggering paths print to console and `webapp/verify-progress.log`. On CI the full suite always runs.
  - **Full-suite runtime (measured 2026-07-17, #534): ~10–11 min** on an idle dev box — the bulk is the 360-node dual-projection browser suite, not agent startups (UI-only e2e tests use a lightweight stub child; only the #444 replay pin spawns real Claude); a routed narrow run is far faster (~90s for a static-asset diff). The gate streams per-test progress + slowest-test timings to gitignored `webapp/verify-progress.log`; on a slow or seemingly-wedged run (>~15 min), read its last `START` line to name the stuck test before killing anything.
- **Restart and verify before hand-off:** the running webapp has no hot-reload — code edits do nothing until the `:8445` process is restarted. After the pre-ship gate passes, restart it so I can immediately test on the phone, *unless I said not to*. The canonical restart is **`tray.bat --restart`** — orphan-proof reclaim-then-start: it kills the tray subtree (tray + webapp `:8445` + cloudflared), reclaims `:8445` by PID scoped to this repo's `.venv` (CommandLine-matched), then starts fresh. Run `--restart`, don't hand-roll the kill. **`:8446` session-host is excluded from that reclaim and survives** — it's spawned detached at start (`cmd /c start`, re-parented out of the tray subtree per project-scaffolding#35) and the fresh tray re-adopts it, so `tray.bat --restart` preserves open Coding/PTY sessions (including one hosted on `:8446` itself) and is safe to run from inside such a session. It never restarts `:8446` itself — see `## session-host` below. After restarting, confirm the new build is live with a bounded poll of `GET /api/version` (hard timeout + attempt cap, fail loud) — `git_sha` should match `HEAD` and `asset_hash` should have changed — and report that build line. Don't hand off "done" with a stale process still serving.
- **A session-host change is not live until `:8446` itself restarts (#615).** A diff touching `src/session_host.py` or `app/session_host/` can merge, pass a fully green gate, and go through a correct `tray.bat --restart` while the running session-host keeps executing days-old code, silently (bit live #611). **Before reporting a session-host-path change as shipped**, check `GET /api/version`'s `session_host` block: `{"reachable", "git_sha", "started_at", "stale", "stale_relevant"}` — `git_sha` is the *loaded* SHA (captured once at that process's own start, not live git state); `stale` is `true` when it differs from the repo's resolved `origin/main` tip (re-resolved fresh on every call — **not** the primary checkout's current branch, which can transiently sit on an unrelated feature branch while a worker occupies the tree, under-reporting `stale_relevant` as `false`, #641); `stale_relevant` scopes it to whether a declared session-host path was actually touched between the loaded SHA and that resolved ref. Both read `null` (never a confident false) when either SHA, or the diff itself, can't be resolved. **Check `stale_relevant`, not raw `stale`, before deciding a restart is warranted** — `stale_relevant: true` means **report the change as merged but not yet live**, never as shipped; `stale_relevant: false` with `stale: true` means nothing to restart for. **Do not restart `:8446` to "fix" this** as a side effect of finishing an issue: it kills every live PTY on the machine, including any standing fleet chief. See `## session-host` for the one supported restart path.

## session-host
- what/why: the `:8446` session-host (`src/session_host.py`, `app/session_host/`) hosts the user's live Coding/PTY sessions. It is spawned detached from the tray subtree (`cmd /c start`) so a `taskkill /T` subtree kill can't reach it, and is deliberately excluded from `tray.bat --restart`'s port-reclaim sweep to protect those live sessions (#611/#615).
- update command: `scripts/restart-session-host.ps1 -Confirm` (confirmation-gated, manual/operator-only — kills every live PTY including a standing fleet chief; never wired into a normal ship flow; bare, without `-Confirm`, prints the warning and exits 1, does nothing). Wraps `tray_lifecycle.ps1 reclaim -Ports 8446` (same as the tray's own Quit path), then `tray.bat --restart` (spawns a fresh session-host since none is left to adopt), then polls `/api/version` to confirm `session_host.stale_relevant` flips to `false`.
- liveness signal: `GET /api/version`'s `session_host.stale_relevant` (raw sha-diff fact lives in `session_host.stale`; `stale_relevant` scopes it to whether a declared path here was actually touched — #635)
- NOT restarted/deployed by: `tray.bat --restart`

## CI expectations
- Workflow `.github/workflows/e2e.yml`, job `verify-before-ship`, on every PR (and on push to `main`). **Advisory, not required** (no branch protection) — the local gate (`scripts/verify-before-ship.ps1`) is the contract.
- Typical green: **~8 min** (re-baselined by #534 — formerly-skipped UI-terminal e2e tests now run on CI against the lightweight stub child, only real-Claude tests still skip there; first post-#534 run 8m15s). Investigate at **>12 min**; the job self-caps at **20 min**, so a wedge is a fast red, never a 6h hang.
- Flaky leg — **PTY-input-delivery** e2e tests (compose/paste/keys/reconnect, both Chromium and WebKit/iPhone projections) intermittently time out on the slower hosted runner (#58). Mitigated (#184): CI sets `E2E_LOG_POLL_DEADLINE_MS=20000` (5s local default), the job sets `timeout-minutes: 15`, and `pytest-timeout` (`timeout=120`, thread method) aborts any single hung test with a stack dump. A wedge/timeout is a flake, not the diff.
- Flaky leg — `test_kill_from_terminal_view_stops_and_returns_to_list[webkit]` (#253) intermittently times out waiting for `#terminalOverlay` to hide (#286): `stopSession()` awaits the host's whole graceful-then-force stop window (5s grace + force) plus two network hops before hiding the overlay. Mitigated (#286): the `to_be_hidden` budget is env-tunable via `E2E_STOP_OVERLAY_HIDE_MS` (20s local default; CI widens it to 30s in e2e.yml). A single red is a flake, not the diff — rerun once.
- Flaky leg — **load**-sensitive, not input-delivery: `test_reconnect_replay_does_not_duplicate_scrollback[webkit]` (#444's dup-scrollback pin) times out waiting for a typed marker to echo back through a **real Claude Code process's** composer (#678) — the one assertion #534 kept on the real agent, not the stub child — so it degrades with how many *other* live agent PTYs the box is hosting, not with runner slowness alone. Mitigated (#678): the wait is env-tunable via `E2E_REAL_AGENT_ECHO_MS` (60s local default; CI widens it to 90s in e2e.yml), and the timeout names the real-agent cold boot instead of raising a bare Playwright `TimeoutError`. A red here reads as "check host load" (how many live PTYs are running), not "rerun and hope" and not "it's the diff."
- **Convention — mock non-deterministic boot fetches before `goto()`, don't widen a timeout** (#510, fixed). `apps.js::refreshGitStatus` calls `renderBoard()` whenever the Board tab is active regardless of an open drawer (unlike `fetchBoard()`'s poll, which self-gates on `state.boardExpanded`), so a late `/api/claude-code/git-status` response silently rebuilds the drawer's DOM out from under Playwright's click. Mock it before navigation — the pattern `test_backlog_cards_color_coded_from_shared_git_cache` already uses.
- **Convention — never assert on a raw `evaluate()` / `bounding_box()` read of a polled-re-render surface** (#680). Mocking the boot fetches above is necessary but *not* sufficient: `renderBoard()` unconditionally calls `list.replaceChildren()` on every column and `fetchBoard()` re-renders every `BOARD_POLL_MS` (5s) while the Board tab is up with no drawer open, so any board test running longer than 5s eventually reads across a rebuild. Playwright resolves a locator to an element handle and *then* reads from it, so a rebuild in between returns an artifact instead of raising — WebKit gives `''` from `getComputedStyle` (shorthand **and** longhand), `None` from `bounding_box()`, and `0` for `scrollWidth`/`clientWidth` (measured: 3 bad reads in 700 with every fetch stubbed, at the 5s cadence). Auto-retrying `expect()` assertions re-resolve and are immune, so prefer `expect(...).to_have_css(...)` over a raw `getComputedStyle` read; where a raw geometry read is unavoidable, wrap it in `tests/e2e/conftest.py::stable_read`, which retries past the artifact without weakening the assertion.
- Self-naming hangs (#186): the e2e suite caps the **default Playwright action + navigation timeout** at 15s (`tests/e2e/conftest.py`, `E2E_DEFAULT_TIMEOUT_MS`-tunable) vs Playwright's own 30s default, so a single auto-waiting `.click()`/`goto`/`wait_for_selector` with no explicit `timeout=` fails fast with a `TimeoutError` that *names the locator*, instead of stacking opaque 30s waits toward the 120s `pytest-timeout` black box. `expect()` assertions keep their own 5s default. A red from this is still a flake on a loaded runner — but a diagnosable, named one.
- CI's only signal beyond the local gate is the **e2e suite** (skipped locally). Its e2e surface = `app/webapp/`, the session-host / PTY layer (`src/session_host*.py`, `src/launcher.py`), `tests/e2e/`, and static assets. A diff touching **none** of these gains nothing from CI.
