# Project Instructions

## This repository
Phone-first launcher hub for the rest of the home stack. Five tabs: **Coding**, **Apps**, **Jobs**, **Life OS** and **Board** (fleet kanban: the chief's plan and the questions it waits on you for, counted in the Board header and the tab badge from every tab), plus **Settings** behind the ⚙ gear in every page header. Sister project to `photo-ocr` and `voice-transcriber` (same conventions, auth model, Cloudflare tunnel pattern). Setup and usage: `README.md` (an index into `docs/`).

**Adding a coding agent?** Follow `fleet-config`'s [`docs/adding-a-coding-harness.md`](https://github.com/ferraroroberto/fleet-config/blob/main/docs/adding-a-coding-harness.md) (fleet-config#491) — the `fleet-config` side first (context file, skills, hooks, Board state, model tiers), then this repo's (`src/agents.py` entry, brand icon, flag builder, launch-router dispatch, README). Probe per-harness facts, never assume them.

**Project specifics:**

- **Stack:** FastAPI + vanilla JS — **not** Streamlit; do not introduce Streamlit.
- **Config & secrets:** no `.env`. Project config in `config/config.json` (committed template only); runtime UI prefs + secrets in `config/webapp_config.json` (gitignored).
- **Registries:** apps in `config/apps.json` (gitignored, committed sample `config/apps.sample.json`), every row carrying a `kind` — `streamlit` | `webapp` | `tunnel` | `tray` — which back the **Apps** tab; jobs in `config/jobs.json`. **Coding** and **Life OS** need no registry (they list directories live).
- **Life's skill rows swipe (#1503).** The gesture is `static/swipe-row.js` behind `actionRow`'s optional `swipe` field. Code's rows and toolbar must stay byte-identical (goldens in `test_life_tab_glance.py` and `test_resume_toggle.py`). A swipe can't be judged in a desktop engine: thresholds are a plain-Node test (`tests/js/swipe_row.test.mjs`); the real check is on the iPhone.
- **Every `git` spawn goes through `src/git_utils.run_git` (#1111).** It carries `git_env()`'s `GIT_OPTIONAL_LOCKS=0`; this repo is the fleet's only *fleet-wide* git reader (`/api/claude-code/git-status` fans `git status` across every sibling repo), so a spawn without it strands 0-byte `.git/index.lock` files fleet-wide (fleet-config#939, #667). `tests/test_git_spawn_gate.py` fails the build on a hand-rolled `subprocess.run(["git", ...])` under `src/` or `app/`. Never delete a stale lock you find, report it.
- **Comment ratchet (#1751).** The gate counts `#NNN` references inside product-code comments per file against `.comment-ratchet-baseline.json` and fails when a file's count rises; exit 3 (a file could not be scanned) is a failure, never a pass. `scripts/comment_ratchet.py` is the scaffold's script, vendored byte-for-byte (`.fleet.toml` `[vendored]`, `[comment_ratchet]`); mechanism: project-scaffolding `docs/comment-ratchet.md`. Lower the baseline with `scripts/comment_ratchet.py --update-baseline` after rewording a comment; wording owned by fleet-config#1517.
- **Test-to-code ratchet (#1753).** The gate fails when code lines under `tests/` over `src/` + `app/` rise above `.fleet.toml` `[test_weight] ratio_ceiling`; exit 3 (count not established) is a failure. After a trim, `python -m scripts.suite_weight_ratchet --update` lowers it; `--raise-ceiling` is the only way up, and its PR says why. Detail: `docs/verification.md`.
- **Docs links resolve (#1752).** `tests/test_docs_links.py` fails the build on a relative link or `#anchor` in `README.md`, `CLAUDE.md` or `docs/*.md` that does not resolve; fix a moved section's inbound links in the same PR.
- **Verification — the pre-ship gate is `pwsh -File scripts/verify-before-ship.ps1`** (boots its own disposable webapp + session-host, no tray needed); run it before declaring any webapp/launcher/session-host change done. Detail: [`docs/verification.md`](docs/verification.md).
  - **Never pipe the gate (#1086).** A pipeline's status is its *last* command's, so `verify-before-ship.ps1 | tail -40` reports `tail`'s exit code. Redirect and read the file: `pwsh -File scripts/verify-before-ship.ps1 > gate.log 2>&1; echo "exit=$?"` then `tail -40 gate.log`. Where a pipe is unavoidable, assert on the final line, `GATE-RESULT: PASS` / `GATE-RESULT: FAIL`; its *absence* (killed, timed out, never parsed) is not a pass either. Under bash, `${PIPESTATUS[0]}` works too.
  - Dev loop with the tray up: `.\scripts\run-e2e.ps1` (both projections) or `--browser chromium` for a faster pass. Targeting the live `:8445` tray is an explicit opt-in (#386): the script sets `LAUNCHER_E2E_LIVE=1`; a bare `pytest tests/e2e` (no `LAUNCHER_E2E_AUTOBOOT=1` either) exits with a guard message. Never point ad-hoc pytest at the live webapp.
  - Suite = `tests/e2e/test_smoke.py` plus one regression test per closed iPhone bite; `tests/e2e/` is its own index. PTY write-boundary byte-loss has a non-browser guard, `tests/test_session_host_pty_realpty.py`. Non-browser suite alone: `pytest tests -m "not smoke" -v`.
  - **Modal contract (#545): a dialog has a header ✕ close plus one full-width primary action.**
  - **WebKit/iPhone is opt-in per test (#1220):** a browser test runs on Chromium, and on WebKit/iPhone too only with the `iphone` marker — layout/geometry, touch targets, nav, composer/keyboard input, safe-area, engine branches. `conftest.py::pytest_collection_modifyitems` deselects every other WebKit node, and `tests/test_e2e_iphone_projection.py` fails the build when a test that measures layout, taps or reads `browser_name` lacks the marker. A new test that measures anything visual gets `@pytest.mark.iphone`.
  - **The e2e phase is diff-proportionate (#568):** byte-compile + the non-e2e pytest suite always run; the *browser* slice is routed against `main` by `scripts/classify_e2e.py` (the scaffold's classifier, byte-verbatim; rules in `.fleet.toml` `[e2e]`, #955): a static-asset-only diff runs Chromium-only smoke, a backend/docs-only diff runs no browser suite, and any `.js`/`.css`/real-page/session-host/e2e-test change (or any mixed/ambiguous diff) runs the full dual-projection suite, narrowed to one declared `[[e2e.surface]]` (Board, Life OS) when every such path sits in it. Uncertainty escalates to full, never narrows; the tier + triggering paths print to console and `webapp/verify-progress.log`.
  - **Gate runtime is a property of this host: re-measure before trusting any figure** (#1512, #1515). Worker counts: `$UnitDefaultWorkers` (override `UNIT_WORKERS`) and `$E2EDefaultWorkers` (override `E2E_WORKERS`; `1` = serial) in `scripts/e2e-gate-route.ps1`. Keep the disposable webapp scoped to the launch target (`pin_launch_target`, #1512). Tests marked `serial` run after the workers. Progress goes to gitignored `webapp/verify-progress.log` (lines tagged `[gw1]`); on a run that looks wedged, every `START` without a matching `DONE` is a test still in flight — read them all before killing anything.
- **Restart and verify before hand-off** — procedure: [`docs/restart-and-liveness.md`](docs/restart-and-liveness.md). Recipe: after the gate passes (unless I said not to), `tray.bat --restart` (reclaims `:8445`, preserves `:8446`), then a bounded poll of `GET /api/version` until `git_sha` matches `HEAD`. A session-host-path change is not live until `:8446` restarts: gate on `session_host.stale_relevant` (`true` → report "merged, not yet live"), and never restart `:8446` as a side effect of finishing an issue.

## session-host
- what/why: the `:8446` session-host (`app/session_host/`, `app/__init__.py`, `src/__init__.py`, `src/agents.py`, `src/app_config.py`, `src/audit.py`, `src/build_info.py`, `src/chief_session_end.py`, `src/diagnostics.py`, `src/env_path.py`, `src/git_utils.py`, `src/session_host.py`, `src/session_host_composer.py`, `src/session_host_input.py`, `src/session_host_scan.py`, `src/subprocess_flags.py`, `src/vt_snapshot.py`) hosts the user's live Coding/PTY sessions. Spawned detached from the tray subtree (`cmd /c start`, re-parented per project-scaffolding#35) so a `taskkill /T` subtree kill can't reach it, and the fresh tray re-adopts it; deliberately excluded from `tray.bat --restart`'s port-reclaim sweep to protect those live sessions (#611/#615).
- path list: that list is the session-host server module's **first-party import closure** — `src.session_host_paths.session_host_import_closure()` computes it statically from the import graph and `tests/test_session_host_paths.py` fails when the declaration drifts from it (#923). Add the module here in the same PR that makes the session-host import it — the test tells you. Out of scope: the argparse bootstrap above the server module (launcher.py → the CLI dispatcher). Deliberately *kept off* the closure: `src/console_input.py` (#967), which `RemoteSession.submit_input` runs as a fresh `python -m` subprocess per message — a fix there is live on the next send without a `:8446` restart.
- update command: `scripts/restart-session-host.ps1 -Confirm` (confirmation-gated, manual/operator-only — kills every live PTY including a standing fleet chief; never wired into a normal ship flow; bare, without `-Confirm`, it exits 1 and does nothing). Wraps `tray_lifecycle.ps1 reclaim -Ports 8446`, then `tray.bat --restart`, then polls `/api/version` until `session_host.stale_relevant` is `false`.
- liveness signal: `GET /api/version`'s `session_host.stale_relevant` (raw sha-diff fact lives in `session_host.stale`; `stale_relevant` scopes it to whether a declared path here was actually touched — #635)
- NOT restarted/deployed by: `tray.bat --restart`

## CI expectations
- Workflow `.github/workflows/e2e.yml`, job `verify-before-ship`, on every PR and push to `main`. **Advisory, not required** — the local gate is the contract.
- **CI is the clean-machine half only (#1041): byte-compile plus the non-e2e pytest suite, no browser suite** (`e2e-gate-route.ps1` routes CI to tier `skip`, pinned by `tests/test_verify_gate_route.py`). It covers what a local run cannot: a fresh `.venv` from `requirements.txt` against committed files only. A browser-visible change is proven only by the local gate on this box. The job self-caps at 10 min.

## E2E browser suite — local gate only
Reasoning and examples: [`docs/e2e-conventions.md`](docs/e2e-conventions.md).

- **A timeout in a flaky leg is a flake, not the diff — rerun once:** PTY-input-delivery tests (#58, `E2E_LOG_POLL_DEADLINE_MS`), the webkit kill test (#286, `E2E_STOP_OVERLAY_HIDE_MS`). The real-agent replay pin (#444, `E2E_REAL_AGENT_ECHO_MS`) is load-sensitive: a red means check host load, not "rerun and hope".
- **Mock non-deterministic boot fetches before `goto()`, don't widen a timeout** (#510).
- **Drive a poll with the fake clock (`tests/e2e/_fake_clock.py`), wait on the request (`wait_until`, `flush_requests`), never sleep on a guess** (#1376).
- **Never assert on a raw `evaluate()` / `bounding_box()` read of a polled-re-render surface** (#680): use auto-retrying `expect()`, else `stable_read` / `stable_eval` (#1346).
- **A test that opens the terminal overlay uses `E2E_OVERLAY_OPEN_MS` (#887), never a literal.**
- **The default Playwright action + navigation timeout is capped at 15s** (`E2E_DEFAULT_TIMEOUT_MS`, #186) so a hang names its locator.
