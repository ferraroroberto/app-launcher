# Project Instructions

## This repository
Phone-first launcher hub for the rest of the home stack. Six tabs: **Coding**, **Apps**, **Jobs**, **Life OS**, **Board** (fleet kanban, incl. the dispatch bar's chat mode talking to a standing fleet chief), and **Settings**. Sister project to `photo-ocr` and `voice-transcriber` (same conventions, auth model, Cloudflare tunnel pattern). Setup, layout, and tab-by-tab usage: `README.md`.

**Adding a coding agent?** Follow `fleet-config`'s [`docs/adding-a-coding-harness.md`](https://github.com/ferraroroberto/fleet-config/blob/main/docs/adding-a-coding-harness.md) (fleet-config#491) — both halves in dependency order: the `fleet-config` side (context file, skills, hooks, Board state, model tiers), then this repo's (`src/agents.py` entry, brand icon, flag builder, launch-router dispatch, README). Probe per-harness facts, never assume them; don't re-derive the procedure from a prior agent's diff.

**Project specifics:**

- **Stack:** FastAPI + vanilla JS — **not** Streamlit; do not introduce Streamlit.
- **Config & secrets:** no `.env`. Project config in `config/config.json` (committed template only); runtime UI prefs + secrets in `config/webapp_config.json` (gitignored).
- **Registries:** apps in `config/apps.json` (gitignored, committed sample `config/apps.sample.json`), every row carrying a `kind` — `streamlit` | `webapp` | `tunnel` | `tray` — which back the **Apps** tab; jobs in `config/jobs.json`. **Coding** and **Life OS** need no registry (they list directories live).
- **Verification — the pre-ship gate is `pwsh -File scripts/verify-before-ship.ps1`** (boots its own disposable webapp + session-host, no tray needed); run it before declaring any webapp/launcher/session-host change done. Detail: README "Playwright smoke + regression tests" and "Verifying changes before ship".
  - Dev loop with the tray up: `.\scripts\run-e2e.ps1` (both projections) or `--browser chromium` for a faster pass. Targeting the live `:8445` tray is an explicit opt-in (#386) — the script sets `LAUNCHER_E2E_LIVE=1`; a bare `pytest tests/e2e` without it (and without `LAUNCHER_E2E_AUTOBOOT=1`) exits with a guard message. Never point ad-hoc pytest runs at the live webapp the phone is using.
  - Suite = `tests/e2e/test_smoke.py` plus one regression test per closed iPhone bite; `tests/e2e/` is its own index — don't re-enumerate the closed bites here. Byte-loss at the PTY write boundary has a non-browser real-PTY guard, `tests/test_session_host_pty_realpty.py` (in the `not smoke` suite). Non-browser suite alone: `pytest tests -m "not smoke" -v`.
  - **Modal contract (#545, supersedes #484): a dialog has a header ✕ close plus one full-width primary action** — new dialogs follow this shape.
  - **The e2e phase is diff-proportionate (#568):** byte-compile + the non-e2e pytest suite always run, but the *browser* slice is routed by `scripts/classify_e2e.py` against `main` — a static-asset-only diff runs Chromium-only smoke (~15s), a backend/docs-only diff runs no browser suite, and any `.js`/`.css`/real-page/session-host/e2e-test change (or any mixed/ambiguous/unrecognized diff) runs the full dual-projection suite. Routing is fail-safe: uncertainty escalates to full, never narrows; the chosen tier + triggering paths print to console and `webapp/verify-progress.log`. On CI the full suite always runs.
  - **Full-suite runtime ~21 min** on this dev box (re-baselined 2026-09-11, #887) — a property of *this* host, not of the suite: re-measure before trusting it. The bulk is the 360-node dual-projection browser suite, not agent startups (UI-only e2e tests use a lightweight stub child; only the #444 replay pin spawns real Claude); a routed narrow run is far faster (~90s for a static-asset diff). The gate streams per-test progress + slowest-test timings to gitignored `webapp/verify-progress.log`; on a run that looks wedged (>~30 min), read its last `START` line to name the stuck test before killing anything.
- **Restart and verify before hand-off:** the running webapp has no hot-reload — code edits do nothing until the `:8445` process is restarted. After the pre-ship gate passes, restart it so I can immediately test on the phone, *unless I said not to*. The canonical restart is **`tray.bat --restart`** — orphan-proof reclaim-then-start: it kills the tray subtree (tray + webapp `:8445` + cloudflared), reclaims `:8445` by PID scoped to this repo's `.venv` (CommandLine-matched), then starts fresh. Run `--restart`, don't hand-roll the kill. **`:8446` session-host is excluded from that reclaim and survives** (mechanism: `## session-host` below), so `--restart` preserves open Coding/PTY sessions — including one hosted on `:8446` itself — is safe to run from inside such a session, and never restarts `:8446`. After restarting, confirm the new build is live with a bounded poll of `GET /api/version` (hard timeout + attempt cap, fail loud) — `git_sha` should match `HEAD` and `asset_hash` should have changed — and report that build line. Don't hand off "done" with a stale process still serving.
- **A session-host change is not live until `:8446` itself restarts (#615).** A diff touching `src/session_host.py` or `app/session_host/` can merge, pass a fully green gate, and go through a correct `tray.bat --restart` while the running session-host keeps executing days-old code, silently (#611). **Before reporting a session-host-path change as shipped**, read `GET /api/version`'s `session_host` block — `{"reachable", "git_sha", "started_at", "stale", "stale_relevant"}`. `git_sha` is the *loaded* SHA (captured once at that process's own start, not live git state); `stale` means it differs from the repo's resolved `origin/main` tip, re-resolved fresh on every call — **not** the primary checkout's current branch, which can transiently sit on an unrelated feature branch while a worker occupies the tree, under-reporting `stale_relevant` as `false` (#641); `stale_relevant` scopes that to whether a declared session-host path was actually touched between the loaded SHA and that resolved ref. Both read `null` (never a confident false) when either SHA, or the diff itself, can't be resolved. **Gate on `stale_relevant`, not raw `stale`** — `true` means **report the change as merged but not yet live**, never as shipped; `false` with `stale: true` means nothing to restart for. **Do not restart `:8446` to "fix" this** as a side effect of finishing an issue: it kills every live PTY on the machine, including any standing fleet chief. See `## session-host` for the one supported restart path.

## session-host
- what/why: the `:8446` session-host (`app/session_host/`, `app/__init__.py`, `src/__init__.py`, `src/agents.py`, `src/app_config.py`, `src/audit.py`, `src/build_info.py`, `src/diagnostics.py`, `src/env_path.py`, `src/git_utils.py`, `src/session_host.py`, `src/session_host_input.py`, `src/session_host_scan.py`, `src/subprocess_flags.py`, `src/vt_snapshot.py`) hosts the user's live Coding/PTY sessions. Spawned detached from the tray subtree (`cmd /c start`, re-parented per project-scaffolding#35) so a `taskkill /T` subtree kill can't reach it, and the fresh tray re-adopts it; deliberately excluded from `tray.bat --restart`'s port-reclaim sweep to protect those live sessions (#611/#615).
- path list: that list is the session-host server module's **first-party import closure**, not a hand-picked set — `src.session_host_paths.session_host_import_closure()` computes it statically from the real import graph and `tests/test_session_host_paths.py` fails when the declaration drifts from it (#923: `src/audit.py` was imported and never declared, so a change to it could not make `stale_relevant` say `true`). Add the module here in the same PR that makes the session-host import it — the test tells you. Out of scope by decision: the argparse bootstrap above the server module (launcher.py → the CLI dispatcher), which every launcher process loads identically, so a change there is not a session-host change.
- update command: `scripts/restart-session-host.ps1 -Confirm` (confirmation-gated, manual/operator-only — kills every live PTY including a standing fleet chief; never wired into a normal ship flow; bare, without `-Confirm`, prints the warning and exits 1, does nothing). Wraps `tray_lifecycle.ps1 reclaim -Ports 8446` (same as the tray's own Quit path), then `tray.bat --restart` (spawns a fresh session-host since none is left to adopt), then polls `/api/version` to confirm `session_host.stale_relevant` flips to `false`.
- liveness signal: `GET /api/version`'s `session_host.stale_relevant` (raw sha-diff fact lives in `session_host.stale`; `stale_relevant` scopes it to whether a declared path here was actually touched — #635)
- NOT restarted/deployed by: `tray.bat --restart`

## CI expectations
- Workflow `.github/workflows/e2e.yml`, job `verify-before-ship`, on every PR (and on push to `main`). **Advisory, not required** (no branch protection) — the local gate (`scripts/verify-before-ship.ps1`) is the contract.
- Typical green: **~8 min** (re-baselined by #534; on CI only real-Claude tests still skip). Investigate at **>12 min**; the job self-caps at **20 min**, so a wedge is a fast red, never a 6h hang.
- Flaky leg — **PTY-input-delivery** e2e tests (compose/paste/keys/reconnect, both Chromium and WebKit/iPhone projections) intermittently time out on the slower hosted runner (#58). Mitigated (#184): CI sets `E2E_LOG_POLL_DEADLINE_MS=20000` (5s local default), the job sets `timeout-minutes: 15`, and `pytest-timeout` (`timeout=120`, thread method) aborts a hung test with a stack dump. A wedge/timeout is a flake, not the diff.
- Flaky leg — `test_kill_from_terminal_view_stops_and_returns_to_list[webkit]` (#253) intermittently times out waiting for `#terminalOverlay` to hide (#286): `stopSession()` awaits the host's full 5s-grace-then-force stop window plus two network hops before hiding the overlay. Mitigated (#286): the `to_be_hidden` budget is env-tunable via `E2E_STOP_OVERLAY_HIDE_MS` (20s local default; CI widens it to 30s in e2e.yml). A single red is a flake, not the diff — rerun once.
- Flaky leg — **load**-sensitive, not input-delivery: `test_reconnect_replay_does_not_duplicate_scrollback[webkit]` (#444's dup-scrollback pin) times out waiting for a typed marker to echo back through a **real Claude Code process's** composer (#678), so it degrades with how many *other* live agent PTYs the box is hosting, not with runner slowness alone. Mitigated (#678): the wait is env-tunable via `E2E_REAL_AGENT_ECHO_MS` (was 60s local, now **90s locally too** per the #887 follow-up; CI sets 90s in e2e.yml), and the timeout names the real-agent cold boot instead of raising a bare Playwright `TimeoutError`. Typical is ~9s; the tail is what bites. A red here means **check host load** (how many live PTYs are running) — not the diff, not "rerun and hope". Read the traceback and check *which* wait it names before widening anything. Widening helps the margin; it cannot make a real agent's cold boot deterministic.
- **Convention — mock non-deterministic boot fetches before `goto()`, don't widen a timeout** (#510). A late boot response rebuilds the DOM out from under Playwright's click, and no timeout makes its arrival deterministic. `apps-coding.js::refreshGitStatus` self-gates on `state.boardExpanded` (#512, pinned by `test_board_drawer_survives_git_status_poll_mid_interaction`) so it no longer tears down an open drawer — but with no drawer open a late `/api/claude-code/git-status` response still calls `renderBoard()`, the same rebuild race as the next bullet's poll. Mock it before navigation — the pattern `test_backlog_cards_color_coded_from_shared_git_cache` already uses.
- **Convention — never assert on a raw `evaluate()` / `bounding_box()` read of a polled-re-render surface** (#680). Mocking the boot fetches above is necessary but not sufficient: `renderBoard()` unconditionally `replaceChildren()`s every column and `fetchBoard()` re-renders every `BOARD_POLL_MS` (5s) while the Board tab is up with no drawer open, so any board test running longer than 5s eventually reads across a rebuild. Playwright resolves a locator to an element handle and *then* reads from it, so a rebuild in between returns an artifact instead of raising — WebKit gives `''` from `getComputedStyle` (shorthand **and** longhand), `None` from `bounding_box()`, and `0` for `scrollWidth`/`clientWidth` (measured: 3 bad reads in 700 with every fetch stubbed, at the 5s cadence). Auto-retrying `expect()` assertions re-resolve and are immune: prefer `expect(...).to_have_css(...)` over a raw `getComputedStyle` read; where a raw geometry read is unavoidable, wrap it in `tests/e2e/conftest.py::stable_read`, which retries past the artifact without weakening the assertion.
- **One shared budget for opening the terminal overlay (#887): `E2E_OVERLAY_OPEN_MS`, 30s, in `tests/e2e/conftest.py`.** ~19 modules must open the terminal before they can assert anything, and each had a hardcoded `timeout=10_000` — *tighter* than the 15s default below, for the slowest operation in the suite (measured here: overlay open p50 3.9s / max 8.0s Chromium, p50 4.5s / **max 12.2s** WebKit, already over the old budget). That one number was the gate's dominant failure mode — 8–17 reds per run, a different set every time, clean `main` failing at the same rate. **Any new test that opens the terminal must use this constant, never a literal**; the per-leg vars above each widen exactly one test, which is how the other ~35 members of the pool were left marginal.
- Self-naming hangs (#186): the e2e suite caps the **default Playwright action + navigation timeout** at 15s (`tests/e2e/conftest.py`, `E2E_DEFAULT_TIMEOUT_MS`-tunable) vs Playwright's own 30s default, so a single auto-waiting `.click()`/`goto`/`wait_for_selector` with no explicit `timeout=` fails fast with a `TimeoutError` that *names the locator*, instead of stacking opaque 30s waits toward the 120s `pytest-timeout` black box. `expect()` assertions keep their own 5s default. A red here is still a flake on a loaded runner — but a diagnosable, named one.
- CI's only signal beyond the local gate is the **e2e suite** (skipped locally). Its e2e surface = `app/webapp/`, the session-host / PTY layer (`src/session_host*.py`, `src/vt_snapshot.py`, `src/launcher.py`), `tests/e2e/`, and static assets. A diff touching **none** of these gains nothing from CI.
