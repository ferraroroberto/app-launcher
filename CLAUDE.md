# Project Instructions

## This repository
Phone-first launcher hub for the rest of the home stack. Six tabs: **Coding**, **Apps**, **Jobs**, **Life OS**, **Board** (fleet kanban, incl. the dispatch bar's chat mode talking to a standing fleet chief), and **Settings**. Sister project to `photo-ocr` and `voice-transcriber` (same conventions, auth model, Cloudflare tunnel pattern). Setup, layout, and tab-by-tab usage: `README.md`.

**Adding a coding agent?** Follow `fleet-config`'s [`docs/adding-a-coding-harness.md`](https://github.com/ferraroroberto/fleet-config/blob/main/docs/adding-a-coding-harness.md) (fleet-config#491) — both halves in dependency order: the `fleet-config` side (context file, skills, hooks, Board state, model tiers), then this repo's (`src/agents.py` entry, brand icon, flag builder, launch-router dispatch, README). Probe per-harness facts, never assume them; don't re-derive the procedure from a prior agent's diff.

**Project specifics:**

- **Stack:** FastAPI + vanilla JS — **not** Streamlit; do not introduce Streamlit.
- **Config & secrets:** no `.env`. Project config in `config/config.json` (committed template only); runtime UI prefs + secrets in `config/webapp_config.json` (gitignored).
- **Registries:** apps in `config/apps.json` (gitignored, committed sample `config/apps.sample.json`), every row carrying a `kind` — `streamlit` | `webapp` | `tunnel` | `tray` — which back the **Apps** tab; jobs in `config/jobs.json`. **Coding** and **Life OS** need no registry (they list directories live).
- **Verification — the pre-ship gate is `pwsh -File scripts/verify-before-ship.ps1`** (boots its own disposable webapp + session-host, no tray needed); run it before declaring any webapp/launcher/session-host change done. Detail: README "Playwright smoke + regression tests" and "Verifying changes before ship".
  - **Never pipe the gate (#1086).** A pipeline's status is its *last* command's, so `verify-before-ship.ps1 | tail -40` reports the exit code of `tail` — a failed gate read as `exited with code 0`, silently, whatever checks `$?` afterwards. Redirect and read the file instead: `pwsh -File scripts/verify-before-ship.ps1 > gate.log 2>&1; echo "exit=$?"` then `tail -40 gate.log`. Where a pipe is unavoidable, assert on the gate's own final line — `GATE-RESULT: PASS` / `GATE-RESULT: FAIL`, emitted on the pass path, the `Fail` path **and** the unhandled-error path (which previously died on stderr, so a piped caller saw zero lines and exit 0 — a silent empty "success"). Its *absence* now means only that the run was killed, timed out, or never parsed; that is not a pass either. Under bash, `${PIPESTATUS[0]}` works too.
  - Dev loop with the tray up: `.\scripts\run-e2e.ps1` (both projections) or `--browser chromium` for a faster pass. Targeting the live `:8445` tray is an explicit opt-in (#386) — the script sets `LAUNCHER_E2E_LIVE=1`; a bare `pytest tests/e2e` without it (and without `LAUNCHER_E2E_AUTOBOOT=1`) exits with a guard message. Never point ad-hoc pytest runs at the live webapp the phone is using.
  - Suite = `tests/e2e/test_smoke.py` plus one regression test per closed iPhone bite; `tests/e2e/` is its own index — don't re-enumerate the closed bites here. Byte-loss at the PTY write boundary has a non-browser real-PTY guard, `tests/test_session_host_pty_realpty.py` (in the `not smoke` suite). Non-browser suite alone: `pytest tests -m "not smoke" -v`.
  - **Modal contract (#545, supersedes #484): a dialog has a header ✕ close plus one full-width primary action** — new dialogs follow this shape.
  - **The e2e phase is diff-proportionate (#568):** byte-compile + the non-e2e pytest suite always run, but the *browser* slice is routed against `main` by `scripts/classify_e2e.py` (the scaffold's classifier, byte-verbatim; the rules live in `.fleet.toml` `[e2e]`, #955) — a static-asset-only diff runs Chromium-only smoke (~15s), a backend/docs-only diff runs no browser suite, and any `.js`/`.css`/real-page/session-host/e2e-test change (or any mixed/ambiguous/unrecognized diff) runs the full dual-projection suite, narrowed to one declared `[[e2e.surface]]`'s tests (Board, Life OS) when every such path sits in it. Routing is fail-safe: uncertainty escalates to full, never narrows; the chosen tier + triggering paths print to console and `webapp/verify-progress.log`. On CI the browser suite is skipped outright (#1041), so this gate is the only place it runs.
  - **Full-suite runtime ~19 min** on this dev box (re-baselined 2026-09-19 across four full-tier gate runs; previously ~21 min, #887) — a property of *this* host, not of the suite: re-measure before trusting it. The bulk is the dual-projection browser suite (638 collected on 2026-09-20, #1064; the ~19 min above was measured at 596 nodes, so treat it as a floor until re-timed), not agent startups (UI-only e2e tests use a lightweight stub child; only the #444 replay pin spawns real Claude); a routed narrow run is far faster (~90s for a static-asset diff). The gate streams per-test progress + slowest-test timings to gitignored `webapp/verify-progress.log`; on a run that looks wedged (>~30 min), read its last `START` line to name the stuck test before killing anything.
- **Restart and verify before hand-off** — procedure: [`docs/restart-and-liveness.md`](docs/restart-and-liveness.md). Recipe: after the gate passes (unless I said not to), `tray.bat --restart` (reclaims `:8445`, preserves `:8446`), then a bounded poll of `GET /api/version` until `git_sha` matches `HEAD`. A session-host-path change is not live until `:8446` restarts: gate on `session_host.stale_relevant` (`true` → report "merged, not yet live"), and never restart `:8446` as a side effect of finishing an issue.

## session-host
- what/why: the `:8446` session-host (`app/session_host/`, `app/__init__.py`, `src/__init__.py`, `src/agents.py`, `src/app_config.py`, `src/audit.py`, `src/build_info.py`, `src/diagnostics.py`, `src/env_path.py`, `src/git_utils.py`, `src/session_host.py`, `src/session_host_input.py`, `src/session_host_scan.py`, `src/subprocess_flags.py`, `src/vt_snapshot.py`) hosts the user's live Coding/PTY sessions. Spawned detached from the tray subtree (`cmd /c start`, re-parented per project-scaffolding#35) so a `taskkill /T` subtree kill can't reach it, and the fresh tray re-adopts it; deliberately excluded from `tray.bat --restart`'s port-reclaim sweep to protect those live sessions (#611/#615).
- path list: that list is the session-host server module's **first-party import closure**, not a hand-picked set — `src.session_host_paths.session_host_import_closure()` computes it statically from the real import graph and `tests/test_session_host_paths.py` fails when the declaration drifts from it (#923: `src/audit.py` was imported and never declared, so a change to it could not make `stale_relevant` say `true`). Add the module here in the same PR that makes the session-host import it — the test tells you. Out of scope by decision: the argparse bootstrap above the server module (launcher.py → the CLI dispatcher), which every launcher process loads identically, so a change there is not a session-host change. Deliberately *kept off* the closure: `src/console_input.py` (#967), which `RemoteSession.submit_input` runs as a fresh `python -m` subprocess per message and never imports — a fix there is live on the next send without a `:8446` restart.
- update command: `scripts/restart-session-host.ps1 -Confirm` (confirmation-gated, manual/operator-only — kills every live PTY including a standing fleet chief; never wired into a normal ship flow; bare, without `-Confirm`, prints the warning and exits 1, does nothing). Wraps `tray_lifecycle.ps1 reclaim -Ports 8446` (same as the tray's own Quit path), then `tray.bat --restart` (spawns a fresh session-host since none is left to adopt), then polls `/api/version` to confirm `session_host.stale_relevant` flips to `false`.
- liveness signal: `GET /api/version`'s `session_host.stale_relevant` (raw sha-diff fact lives in `session_host.stale`; `stale_relevant` scopes it to whether a declared path here was actually touched — #635)
- NOT restarted/deployed by: `tray.bat --restart`

## CI expectations
- Workflow `.github/workflows/e2e.yml`, job `verify-before-ship`, on every PR (and on push to `main`). **Advisory, not required** (no branch protection) — the local gate (`scripts/verify-before-ship.ps1`) is the contract.
- **Scope since #1041: the clean-machine half only — byte-compile plus the non-e2e pytest suite. CI runs no browser suite.** `e2e-gate-route.ps1` routes CI to tier `skip`, whatever the diff says, pinned by `tests/test_verify_gate_route.py`. What CI is *for* is the half a local run structurally cannot do: a fresh `.venv` from `requirements.txt` on a machine that has never seen this repo, against committed files only — so it catches an uncommitted file, a dev-box-only dependency, a test that passes only on local state, and **drift in an unpinned dependency** (#1041 itself: `fastapi>=0.110` resolved to 0.136 here and 0.141 there, and only the newer one broke the guard-coverage route walk).
- What CI no longer catches, stated plainly: **every browser-visible regression**. A `.js`/`.css`/template/session-host-UI change is now proven only by the local gate on this box — if a lane skips it, or routes it narrow and is wrong, nothing downstream notices. Also lost: the e2e suite's own health on a clean machine (the #470-class "mass-skip still reports green" bug would go unseen) and Playwright browser-install drift.
- Typical green: **~4 min** (deps ~1 min, the ~2450-test non-e2e suite ~3 min). Investigate at **>7 min**; the job self-caps at **10 min**, so a wedge is a fast red, never a 6h hang.

## E2E browser suite — local gate only
*These legs and conventions describe `scripts/verify-before-ship.ps1`'s browser phase, which since #1041 runs **only** on this box. The `E2E_*` budgets below are the local defaults; the CI overrides they used to carry are gone with the CI browser leg.*

- Flaky leg — **PTY-input-delivery** e2e tests (compose/paste/keys/reconnect, both Chromium and WebKit/iPhone projections) intermittently time out under load (#58 — first observed on the slower hosted runner, since #1041 only reachable locally). Mitigated (#184): `E2E_LOG_POLL_DEADLINE_MS` (5s default) is env-tunable, and `pytest-timeout` (`timeout=120`, thread method) aborts a hung test with a stack dump. A wedge/timeout is a flake, not the diff.
- Flaky leg — `test_kill_from_terminal_view_stops_and_returns_to_list[webkit]` (#253) intermittently times out waiting for `#terminalOverlay` to hide (#286): `stopSession()` awaits the host's full 5s-grace-then-force stop window plus two network hops before hiding the overlay. Mitigated (#286): the `to_be_hidden` budget is env-tunable via `E2E_STOP_OVERLAY_HIDE_MS` (20s default). A single red is a flake, not the diff — rerun once.
- Flaky leg — **load**-sensitive, not input-delivery: `test_reconnect_replay_does_not_duplicate_scrollback[webkit]` (#444's dup-scrollback pin) times out waiting for a typed marker to echo back through a **real Claude Code process's** composer (#678), so it degrades with how many *other* live agent PTYs the box is hosting, not with runner slowness alone. Mitigated (#678): the wait is env-tunable via `E2E_REAL_AGENT_ECHO_MS` (was 60s, now **90s** per the #887 follow-up), and the timeout names the real-agent cold boot instead of raising a bare Playwright `TimeoutError`. Typical is ~9s; the tail is what bites. A red here means **check host load** (how many live PTYs are running) — not the diff, not "rerun and hope". Read the traceback and check *which* wait it names before widening anything. Widening helps the margin; it cannot make a real agent's cold boot deterministic.
- **Convention — mock non-deterministic boot fetches before `goto()`, don't widen a timeout** (#510). A late boot response rebuilds the DOM out from under Playwright's click, and no timeout makes its arrival deterministic. `renderBoard()` keeps an open drawer's node (#958), so `apps-coding.js::refreshGitStatus` no longer tears one down (#512, pinned by `test_board_drawer_survives_git_status_poll_mid_interaction`) — but a late `/api/claude-code/git-status` response still rebuilds every other card, the same rebuild race as the next bullet's poll. Mock it before navigation — the pattern `test_backlog_cards_color_coded_from_shared_git_cache` already uses.
- **Convention — never assert on a raw `evaluate()` / `bounding_box()` read of a polled-re-render surface** (#680). Mocking the boot fetches above is necessary but not sufficient: `renderBoard()` rebuilds every card except an open drawer's (#958) and `fetchBoard()` re-renders every `BOARD_POLL_MS` (5s) while the Board tab is up, drawer open or not, so any board test running longer than 5s eventually reads across a rebuild. Playwright resolves a locator to an element handle and *then* reads from it, so a rebuild in between returns an artifact instead of raising — WebKit gives `''` from `getComputedStyle` (shorthand **and** longhand), `None` from `bounding_box()`, and `0` for `scrollWidth`/`clientWidth` (measured: 3 bad reads in 700 with every fetch stubbed, at the 5s cadence). Auto-retrying `expect()` assertions re-resolve and are immune: prefer `expect(...).to_have_css(...)` over a raw `getComputedStyle` read; where a raw geometry read is unavoidable, wrap it in `tests/e2e/conftest.py::stable_read`, which retries past the artifact without weakening the assertion.
- **One shared budget for opening the terminal overlay (#887): `E2E_OVERLAY_OPEN_MS`, 30s, in `tests/e2e/conftest.py`.** ~19 modules must open the terminal before they can assert anything, and each had a hardcoded `timeout=10_000` — *tighter* than the 15s default below, for the slowest operation in the suite (measured here: overlay open p50 3.9s / max 8.0s Chromium, p50 4.5s / **max 12.2s** WebKit, already over the old budget). That one number was the gate's dominant failure mode — 8–17 reds per run, a different set every time, clean `main` failing at the same rate. **Any new test that opens the terminal must use this constant, never a literal**; the per-leg vars above each widen exactly one test, which is how the other ~35 members of the pool were left marginal.
- Self-naming hangs (#186): the e2e suite caps the **default Playwright action + navigation timeout** at 15s (`tests/e2e/conftest.py`, `E2E_DEFAULT_TIMEOUT_MS`-tunable) vs Playwright's own 30s default, so a single auto-waiting `.click()`/`goto`/`wait_for_selector` with no explicit `timeout=` fails fast with a `TimeoutError` that *names the locator*, instead of stacking opaque 30s waits toward the 120s `pytest-timeout` black box. `expect()` assertions keep their own 5s default. A red here is still a flake on a loaded box — but a diagnosable, named one.
- CI's only signal beyond the local gate is now the **clean machine** itself — not a test the local gate doesn't run. Every diff gains something from it (the install and the committed-files-only run apply to all of them), and nothing about it is diff-proportionate.
