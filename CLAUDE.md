# Project Instructions

Canonical instructions for AI coding agents working in this repository. Claude Code reads this file directly as project memory. Other agents (Cursor, Codex, etc.) reach it via the one-line `AGENTS.md` pointer.

## This repository
Phone-first launcher hub for the rest of the home stack. Six tabs: **Coding** (one tap → launcher-owned ConPTY or detached console, across six agents — Claude Code, Codex CLI, Antigravity CLI, GitHub Copilot CLI, Pi, Grok Build — for any project directory under the configured projects folder; the list is the directory listing, no marker files needed), **Apps** (one tap → spawn any registered Streamlit/FastAPI launcher anywhere on disk), **Jobs** (fire one-shot Python scripts or scheduled jobs), **Life OS** (invoke a `life-os` productivity skill and browse its knowledge), **Board** (fleet kanban, five single-purpose columns — #164/#399: Backlog and Done hold issues only (open / closed today), Claude's turn and Your turn hold session cards only (working/idle/unknown/idle-finished / stalled/awaiting-decision/awaiting-input — #608 split the old undifferentiated needs-you four ways so a caller never has to fetch the exchange to tell them apart), Other holds open PRs + failed/stuck jobs; the session-host list is authoritative for launcher-owned presence and `sessions-state.json` supplies agent-aware semantic overlays, while GitHub data is `gh`-fetched server-side on demand only, never on poll; the dispatch bar's **chat** mode (#245) — a `chat` value in the mode select, collapsed from a 4-segment radiogroup in #547 — talks to a standing **fleet chief** — a `label="chief"` PTY session cwd'd in fleet-config whose brain is that repo's `/chief` skill, ensured via `POST /api/board/chief/ensure` and steered by `chief_*` settings in `webapp_config.json`; the crown/tint/kill-confirm/manual-Start are consistent across the Board tab, the Coding tab's session list, and the terminal overlay (#547)), and **Settings** (dirs, scan, theme toggle — #383). Sister project to `photo-ocr` and `voice-transcriber` (same conventions, same auth model, same Cloudflare tunnel pattern), but for kicking off other processes instead of doing work itself. See `README.md` for setup, layout, and usage.

**Adding a seventh coding agent?** Start at `fleet-config`'s [`docs/adding-a-coding-harness.md`](https://github.com/ferraroroberto/fleet-config/blob/main/docs/adding-a-coding-harness.md) (fleet-config#491) — it covers both halves in dependency order: the `fleet-config` side first (context file, skills, hooks, Board state, model tiers), then this repo's side (`src/agents.py` entry, brand icon, flag builder, launch-router dispatch, README), with the per-harness facts that must be probed rather than assumed. Don't re-derive the procedure from reading a prior agent's diff.

**Project specifics:**

- **Stack:** FastAPI + vanilla JS — **not** Streamlit; do not introduce Streamlit.
- **Config & secrets:** there is no `.env`. Project config lives in `config/config.json` (committed template only) and runtime UI prefs + secrets in `config/webapp_config.json` (gitignored).
- The unified app registry lives in `config/apps.json` (gitignored, committed sample in `config/apps.sample.json`). Every row in `apps.json` has a `kind` field: `streamlit` | `webapp` | `tunnel` | `tray` — these back the **Apps** tab. The **Coding** and **Life OS** tabs need no registry; they list directories live. The **Jobs** tab is backed by `config/jobs.json`.
- **Verification:** during a dev loop, run the e2e suite with the tray up — `.\scripts\run-e2e.ps1` (both projections) or `--browser chromium` for a faster pass. Targeting the live `:8445` tray is an explicit opt-in (#386): the script sets `LAUNCHER_E2E_LIVE=1`; a bare `pytest tests/e2e` without it (and without `LAUNCHER_E2E_AUTOBOOT=1`) exits with a guard message — never point ad-hoc pytest runs at the live webapp the phone is using. It runs `tests/e2e/test_smoke.py` plus one regression test per closed iPhone bite — `tests/e2e/` is its own index; don't re-enumerate the closed bites here. **Modal contract (#545, supersedes #484's equal-width Cancel/Save pair): a dialog has a header ✕ close plus one full-width primary action** — new dialogs follow this shape. Byte-loss at the PTY write boundary has a non-browser real-PTY guard, `tests/test_session_host_pty_realpty.py` (in the `not smoke` suite). Before declaring any webapp/launcher/session-host change done, run the pre-ship gate `pwsh -File scripts/verify-before-ship.ps1` (boots its own disposable webapp + session-host — no tray needed). **The e2e phase is diff-proportionate (#568):** byte-compile + the non-e2e pytest suite always run, but the *browser* slice is routed by `scripts/classify_e2e.py` against `main` — a static-asset-only diff runs Chromium-only smoke (~15 s), a backend/docs-only diff runs no browser suite, and any `.js`/`.css`/real-page/session-host/e2e-test change (or any mixed/ambiguous/unrecognized diff) runs the full dual-projection suite. Routing is fail-safe: uncertainty always escalates to full, never narrows; the chosen tier + triggering paths print to console and `webapp/verify-progress.log`. On CI the full suite always runs. **Full-suite runtime contract (measured 2026-07-17, #534): ~10–11 min on an idle dev box** — the bulk is the 360-node dual-projection browser suite, not agent startups (UI-only e2e tests use a lightweight stub child; only the #444 replay pin still spawns real Claude); a routed narrow run is far faster (~90 s for a static-asset diff). The gate streams per-test progress + slowest-test timings to gitignored `webapp/verify-progress.log`; on a slow or seemingly-wedged run (>~15 min), read its last `START` line to name the stuck test before killing anything. See README "Playwright smoke + regression tests" and "Verifying changes before ship" for detail. The non-browser suite alone is `pytest tests -m "not smoke" -v`.
- **Restart and verify before hand-off:** the running webapp has no hot-reload — code edits do nothing until the `:8445` process is restarted. After the pre-ship gate passes, restart the webapp so I can immediately test on the phone, *unless I said not to*. The canonical restart is **`tray.bat --restart`** — orphan-proof reclaim-then-start: it kills the tray subtree (tray + webapp `:8445` + cloudflared), reclaims `:8445` (webapp) by PID scoped to this repo's `.venv` (CommandLine-matched), then starts fresh. **The `:8446` session-host is detach-compliant (project-scaffolding#35):** it is spawned **detached** — re-parented out of the tray subtree via `cmd /c start`, because `taskkill /T` walks the parent-child PID tree and `DETACHED_PROCESS`/`CREATE_NEW_PROCESS_GROUP` do **not** escape it (verified empirically) — it is **excluded from the reclaim sweep**, and the fresh tray **re-adopts** it on start. So `tray.bat --restart` now **preserves the user's open Coding / PTY sessions**, including a Claude Code session hosted on `:8446` — it is safe to run from inside such a session. Run `--restart`, don't hand-roll the kill. Then **confirm the new build is live** with a bounded poll of `GET /api/version` (hard timeout + attempt cap, fail loud) — `git_sha` should match `HEAD` and `asset_hash` should have changed — and report that build line. Don't hand off "done" with a stale process still serving.
- **A session-host change is not live until `:8446` itself restarts — `tray.bat --restart` will never do that for you (#615).** A diff touching `src/session_host.py` or `app/session_host/` can merge, pass a fully green gate, and go through a correct `tray.bat --restart` while the running session-host keeps executing whatever it loaded whenever it last started — days-old code, silently. This bit `#611`'s fix live on 2026-07-27: merged, gate green, webapp restarted and reported live, and the session-host was still running a build three days old — the reported fix was not running at all. **Before reporting a session-host-path change as shipped**, check `GET /api/version`'s `session_host` block: `{"reachable", "git_sha", "started_at", "stale", "stale_relevant"}` — `git_sha` is the *loaded* SHA (captured once at that process's own start, not live git state); `stale` is `true` when it differs from the repo's resolved default remote branch tip (`origin/main`, re-resolved fresh on every call — **not** the primary checkout's current branch, which can transiently sit on an unrelated feature branch while a worker occupies the tree; comparing against that transient branch tip under-reported `stale_relevant` as `false` when the answer was `true`, #641), but that's a raw fact, true after *any* merge anywhere in the repo, not just a session-host one (#635); `stale_relevant` scopes it to whether a declared session-host path (`src/session_host.py`, `app/session_host/`) was actually touched between the loaded SHA and that resolved ref. Both read `null` (never a confident false) when either SHA, or the scoped diff itself, can't be resolved. **Check `stale_relevant`, not raw `stale`, before deciding a restart is warranted** — `stale_relevant: true` means **report the change as merged but not yet live**, never as shipped; `stale_relevant: false` with `stale: true` means the repo has moved on but nothing the session-host loads has changed, so there is nothing to restart for. **Do not restart `:8446` to "fix" this** as a side effect of finishing an issue: it kills every live PTY on the machine, including any standing fleet chief — that is real, immediate cost paid by whoever is mid-work, not a formality. The one supported way to restart it is `pwsh -File scripts/restart-session-host.ps1 -Confirm` — a deliberate, explicit, operator-initiated action only, at a clean boundary (no live sessions mid-work), never unattended and never built into a normal ship flow. (Bare, without `-Confirm`, it prints the warning and exits 1 — does nothing.) It wraps the same `tray_lifecycle.ps1 reclaim -Ports 8446` the tray's own Quit path uses, then `tray.bat --restart` (which then spawns a fresh session-host since none is left to adopt), then polls `/api/version` to confirm `session_host.stale_relevant` actually flipped to `false`.

## session-host
- what/why: the `:8446` session-host (`src/session_host.py`, `app/session_host/`) hosts the user's live Coding/PTY sessions. It is spawned detached from the tray subtree (`cmd /c start`) so a `taskkill /T` subtree kill can't reach it, and is deliberately excluded from `tray.bat --restart`'s port-reclaim sweep to protect those live sessions (#611/#615).
- update command: `scripts/restart-session-host.ps1 -Confirm` (confirmation-gated, manual/operator-only — kills every live PTY including a standing fleet chief; never wired into a normal ship flow)
- liveness signal: `GET /api/version`'s `session_host.stale_relevant` (raw sha-diff fact lives in `session_host.stale`; `stale_relevant` scopes it to whether a declared path here was actually touched — #635)
- NOT restarted/deployed by: `tray.bat --restart`

## CI expectations
- Workflow `.github/workflows/e2e.yml`, job `verify-before-ship`, on every PR (and on push to `main`). **Advisory, not required** (no branch protection) — the local gate (`scripts/verify-before-ship.ps1`) is the contract.
- Typical green: **~8 min** (re-baselined by #534: the formerly-skipped UI-terminal e2e tests now run on CI against the lightweight stub child — only the real-Claude tests still skip there; first post-#534 run measured 8m15s). Investigate at **>12 min**; the job self-caps at **20 min**, so a wedge is a fast red, never a 6 h hang.
- Flaky leg: the **PTY-input-delivery** e2e tests (compose/paste/keys/reconnect, both Chromium and WebKit/iPhone projections) intermittently time out on the slower hosted runner — see #58. Mitigated (#184): CI sets `E2E_LOG_POLL_DEADLINE_MS=20000` (20 s vs the 5 s local default) for input-delivery headroom, the job has `timeout-minutes: 15` so a wedge self-caps to a fast red instead of running to GitHub's 6 h ceiling, and `pytest-timeout` (`timeout=120`, thread method) aborts any single hung test with a stack dump. A wedge/timeout is still a flake, not the diff.
- Flaky leg: `test_kill_from_terminal_view_stops_and_returns_to_list[webkit]` (kill-from-terminal-view, #253) intermittently times out waiting for `#terminalOverlay` to hide — see #286. Same timing class as #58: the kill's `stopSession()` awaits the host's whole graceful-then-force stop window (5 s grace + force) plus two network hops before hiding the overlay, which a fixed budget can exceed on a loaded WebKit projection. Mitigated (#286): the `to_be_hidden` budget is env-tunable via `E2E_STOP_OVERLAY_HIDE_MS` (20 s local default; CI widens it to 30 s in e2e.yml). A single red here is a flake, not the diff — rerun once.
- Flaky leg — **load**-sensitive, not input-delivery: `test_reconnect_replay_does_not_duplicate_scrollback[webkit]` (#444's dup-scrollback pin) times out waiting for a typed marker to echo back through a **real Claude Code process's** composer — see #678. Distinct from #58/#286's timing class: this budget covers a real agent cold boot (the one assertion in this suite #534 deliberately kept on the real agent, not the stub child), so it degrades with how many *other* live agent PTYs the box is hosting at the same time, not with runner slowness alone. Mitigated (#678): the wait is env-tunable via `E2E_REAL_AGENT_ECHO_MS` (60 s local default; CI widens it to 90 s in e2e.yml), and the timeout raises a message naming the real-agent cold boot instead of a bare Playwright `TimeoutError`. A red here reads as "check host load" (how many live PTYs are running), not "rerun and hope" and not "it's the diff."
- **Convention — mock non-deterministic boot fetches before `goto()`, don't widen a timeout** (from #510, now fixed). `apps.js::refreshGitStatus` calls `renderBoard()` whenever the Board tab is active regardless of an open drawer (unlike `fetchBoard()`'s poll, which self-gates on `state.boardExpanded`), so a late `/api/claude-code/git-status` response silently rebuilds the drawer's DOM out from under Playwright's click. Mock it before navigation — the pattern `test_backlog_cards_color_coded_from_shared_git_cache` already uses.
- **Convention — never assert on a raw `evaluate()` / `bounding_box()` read of a polled-re-render surface** (from #680). Mocking the boot fetches above is necessary but *not* sufficient: `renderBoard()` unconditionally calls `list.replaceChildren()` on every column, and `fetchBoard()` re-renders every `BOARD_POLL_MS` (5 s) while the Board tab is up with no drawer open — so any board test running longer than 5 s eventually reads across a rebuild. Playwright resolves a locator to an element handle and *then* reads from it; a rebuild in between makes the read return an artifact instead of raising — WebKit gives `''` from `getComputedStyle` (shorthand **and** longhand), `None` from `bounding_box()`, and `0` for `scrollWidth`/`clientWidth`. Measured: 3 bad reads in 700 with every fetch stubbed, at the 5 s cadence. Auto-retrying `expect()` assertions re-resolve and are immune, so prefer `expect(...).to_have_css(...)` over a raw `getComputedStyle` read; where a raw geometry read is unavoidable, wrap it in `tests/e2e/conftest.py::stable_read`, which retries past the artifact without weakening the assertion. This is the read-side counterpart to the mock-the-boot-fetch rule above — that removes one trigger, this survives the rest.
- Self-naming hangs (#186): the e2e suite caps the **default Playwright action + navigation timeout** at 15 s (`tests/e2e/conftest.py`, `E2E_DEFAULT_TIMEOUT_MS`-tunable) — Playwright's own default is 30 s. So a single auto-waiting `.click()`/`goto`/`wait_for_selector` with no explicit `timeout=` whose target never settles fails fast with a `TimeoutError` that *names the locator*, instead of stacking opaque 30 s waits toward the 120 s `pytest-timeout` black box. `expect()` assertions keep their own 5 s default. A red from this is still a flake on a loaded runner — but now a diagnosable, named one.
- CI's only signal beyond the local gate is the **e2e suite** (skipped locally). Its e2e surface = `app/webapp/`, the session-host / PTY layer (`src/session_host*.py`, `src/launcher.py`), `tests/e2e/`, and static assets. A diff touching **none** of these gains nothing from CI.
