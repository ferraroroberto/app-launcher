# Project Instructions

## This repository
Phone-first launcher hub for the rest of the home stack. Five tabs: **Coding**, **Apps**, **Jobs**, **Life OS** and **Board** (fleet kanban: the chief's plan and the questions it waits on you for, counted in the Board header and the tab badge from every tab), plus **Settings** behind the ⚙ gear in every page header. Sister project to `photo-ocr` and `voice-transcriber` (same conventions, auth model, Cloudflare tunnel pattern). Setup and usage: `README.md` (an index into `docs/`).

**Adding a coding agent?** Follow `fleet-config`'s [`docs/adding-a-coding-harness.md`](https://github.com/ferraroroberto/fleet-config/blob/main/docs/adding-a-coding-harness.md) (fleet-config#491) — the `fleet-config` side first (context file, skills, hooks, Board state, model tiers), then this repo's (`src/agents.py` entry, brand icon, flag builder, launch-router dispatch, README). Probe per-harness facts, never assume them.

**Project specifics:**

- **Stack:** FastAPI + vanilla JS — **not** Streamlit; do not introduce Streamlit.
- **Config & secrets:** no `.env`. Project config in `config/config.json` (committed template only); runtime UI prefs + secrets in `config/webapp_config.json` (gitignored).
- **Registries:** apps in `config/apps.json` (gitignored, committed sample `config/apps.sample.json`), every row carrying a `kind` — `streamlit` | `webapp` | `tunnel` | `tray` — which back the **Apps** tab; jobs in `config/jobs.json`. **Coding** and **Life OS** need no registry (they list directories live).
- **Life's skill rows swipe (#1503).** The gesture is `static/swipe-row.js` behind `actionRow`'s optional `swipe` field. Code's rows and toolbar must stay byte-identical (goldens in `test_life_tab_glance.py` and `test_resume_toggle.py`). A swipe can't be judged in a desktop engine: thresholds are a plain-Node test (`tests/js/swipe_row.test.mjs`); the real check is on the iPhone.
- **Every `git` spawn goes through `src/git_utils.run_git` (#1111).** It carries `git_env()`'s `GIT_OPTIONAL_LOCKS=0`; this repo is the fleet's only *fleet-wide* git reader (`/api/claude-code/git-status` fans `git status` across every sibling repo), so a spawn without it strands 0-byte `.git/index.lock` files fleet-wide (fleet-config#939, #667). The conventions ratchet's `git-wrapper` rule (baseline zero) fails the build on a hand-rolled `git` spawn outside it, and `tests/unit/repo/test_git_spawn_gate.py` pins that the wrapper's own spawns pass `env=`. Never delete a stale lock you find, report it.
- **Ratchets: comment (#1751), static (#1750), docs (#1785), structure (#1799), instruction (#1824), doc-refs (#1827), dead-code (#1832), conventions (#1846).** Each is a gate stage running the scaffold's `scripts/<name>_ratchet.py`, vendored byte-for-byte (`.fleet.toml` `[vendored]`, `[<name>_ratchet]`), and fails on a finding beyond `.<name>-ratchet-baseline.json`. Shared rules: exit 3 (a detector could not run or scan: git unusable, an unparseable or non-UTF-8 file, an unknown shape, a fence or comment that never closes, an unreadable skill description, offline with a cold `npx` cache) is a failure, never a pass; all but comment are never path-routed; `tests/unit/repo/test_ratchet_gate_stages.py` runs the gate's real stage text to pin the exit-3 failure for docs, structure, instruction, doc-refs, dead-code and conventions. Shrink a baseline with `--update-baseline`; `--update-baseline --allow-additions` is the only way to add an entry and shows in review. Detail: `docs/verification.md`.
  - **Comment:** counts `#NNN` references inside product-code comments per file; fails when a file's count rises. Lower the baseline with `scripts/comment_ratchet.py --update-baseline` after rewording a comment; wording owned by fleet-config#1517; mechanism: project-scaffolding `docs/comment-ratchet.md`.
  - **Static:** a duplicate block (`jscpd` via `npx`, Python and JS), an unused import/variable (`ruff` `F401,F841`) or a likely bug or security pattern (the ruff `B` and `S` families, `S113` strict) not in the baseline; existing debt is baselined, not fixed. Needs Node and ruff in the gate's venv.
  - **Docs:** `README.md` past 40 KiB or its baselined size, or `README.md` / `docs/**/*.md` gaining an issue reference, a dated heading or a changelog heading beyond the baseline; existing markers are baselined, not fixed. Docs state the present-tense why, so history goes to git, PRs and issues.
  - **Structure:** file, function and directory size limits, the `src` to `app` import rule and the declared root shape (`.fleet.toml` `shape = "webapp-tray"`). The limits and where new code goes: `docs/layout.md`. A baselined offender may not grow; splitting one is its own issue.
  - **Instruction:** lints `CLAUDE.md`, `AGENTS.md` and every `SKILL.md` (plus the docs a skill links to) with the weekly prompt audit's deterministic rules; fails when a file's hit count for a rule rises or a file passes its size cap (`CLAUDE.md` 200 lines, a `SKILL.md` body 500). A new hit is better reworded than baselined; mechanism: project-scaffolding `docs/instruction-ratchet.md`.
  - **Doc-refs:** `README.md`, `CLAUDE.md` or `docs/**/*.md` naming a repo path, `python -m` module, relative link or loopback port that does not exist and is not in the baseline; the app's own port is `.fleet.toml` `port`, and other services' ports and other repos' paths named on purpose are `[doc_refs_ratchet] allow_refs`. Mechanism: project-scaffolding `docs/doc-refs-ratchet.md`.
  - **Dead-code:** a Python function, class or method that nothing refers to. A framework hook the built-in rules miss goes in `[dead_code_ratchet]` `allow` or `entry_decorators`. A baselined entry is removed by hand together with its definition, because the `--update-baseline` hint misleads here. Mechanism: project-scaffolding `docs/dead-code-ratchet.md`.
  - **Conventions:** a file's count for an enabled rule rising: `no-window` (a subprocess spawn with no `creationflags=`), `logging-not-print` (a diagnostic `print` under `src/` or `app/`), `no-drive-path` (a string literal starting with a drive letter) and `git-wrapper` (a `git` spawn outside `src/git_utils.py`) and `subprocess-timeout` (a blocking `subprocess.run`/`call`/`check_*` with no `timeout=`; baseline zero, and only a foreground or interactive runner carries `# subprocess-timeout-exempt: <why>`) and `no-pwsh-stub` (`pwsh` run as a command in any text file, a 0-byte stub here: write the absolute `C:/Windows/System32/WindowsPowerShell/v1.0/powershell.exe`; a hosted-runner CI step or a line that only names the stub carries `no-pwsh-stub-exempt: <why>`). `login-lockout` (the `/api/login` route not using the vendored `src/login_lockout.py`, #2119). `must-use` (a bare `requests.*` call outside `src/clients/_loopback_http.py`'s pooled session; baseline zero). `secret-compare` is off: `hmac.compare_digest` is called from six modules and no one helper owns it. A call that must break a rule keeps a reasoned `# <rule>-exempt: <why>` marker on or above it. Mechanism: project-scaffolding `docs/conventions-ratchet.md`.
  - **Usage track:** a control with no constant `data-track` id, a `<dialog>` with no `data-track-view`, or an id built at run time fails the gate; the baseline is empty. A JS-built control sets `el.dataset.track = '<area>.<control>'` as a literal; a helper that builds controls for several callers is a `[usage_track_ratchet] builders` entry in `.fleet.toml` and its callers pass `track: '<id>'`. A feature counted on success, with no click, calls `usage.track('<id>')` from `static/usage.js`, never a hidden element that is clicked. Mechanism: project-scaffolding `docs/usage-track-ratchet.md`.
- **Test-to-code ratchet (#1753).** The gate fails when code lines under `tests/` over `src/` + `app/` rise above `.fleet.toml` `[test_weight] ratio_ceiling`; exit 3 (count not established) is a failure. After a trim, `python -m scripts.suite_weight_ratchet --update` lowers it; `--raise-ceiling` is the only way up, and its PR says why. Detail: `docs/verification.md`.
- **Docs links resolve (#1752).** `tests/unit/repo/test_docs_links.py` fails the build on a relative link or `#anchor` in `README.md`, `CLAUDE.md` or `docs/*.md` that does not resolve; fix a moved section's inbound links in the same PR.
- **Verification — the pre-ship gate is `C:/Windows/System32/WindowsPowerShell/v1.0/powershell.exe -File scripts/verify-before-ship.ps1`** (boots its own disposable webapp + session-host, no tray needed); run it before declaring any webapp/launcher/session-host change done. Detail: [`docs/verification.md`](docs/verification.md).
  - **Never pipe the gate (#1086).** A pipeline's status is its *last* command's, so `verify-before-ship.ps1 | tail -40` reports `tail`'s exit code. Redirect and read the file: `C:/Windows/System32/WindowsPowerShell/v1.0/powershell.exe -File scripts/verify-before-ship.ps1 > gate.log 2>&1; echo "exit=$?"` then `tail -40 gate.log`. Where a pipe is unavoidable, assert on the final line, `GATE-RESULT: PASS` / `GATE-RESULT: FAIL`; its *absence* (killed, timed out, never parsed) is not a pass either. Under bash, `${PIPESTATUS[0]}` works too.
  - Dev loop with the tray up: `.\scripts\run-e2e.ps1` (both projections) or `--browser chromium` for a faster pass. Targeting the live `:8445` tray is an explicit opt-in (#386): the script sets `LAUNCHER_E2E_LIVE=1`; a bare `pytest tests/e2e` (no `LAUNCHER_E2E_AUTOBOOT=1` either) exits with a guard message. Never point ad-hoc pytest at the live webapp.
  - Suite = `tests/e2e/shell/test_smoke.py` plus one regression test per closed iPhone bite; `tests/e2e/` is its own index. PTY write-boundary byte-loss has a non-browser guard, `tests/unit/session_host/test_session_host_pty_realpty.py`. Non-browser suite alone: `pytest tests -m "not smoke" -v`.
  - **Screenshot baseline (#1820):** the gate's last stage compares `tests/e2e/shots/` (five tabs, phone + desktop, light + dark; fictional data) via the vendored `scripts/shot_baseline.py`; a move-only PR quotes `shot baseline: PASS -- N of N ... 0 drifted` and touches no PNG. A deliberate UI change re-baselines in the same PR: `LAUNCHER_E2E_AUTOBOOT=1 python -m pytest tests/e2e/screens/test_screen_shots.py`, check `git diff --stat -- tests/e2e/shots`, `git add tests/e2e/shots`. Detail: [`docs/verification.md`](docs/verification.md).
  - **Modal contract (#545): a dialog has a header ✕ close plus one full-width primary action.**
  - **WebKit/iPhone is opt-in per test (#1220):** only a test marked `iphone` also runs on WebKit/iPhone, and a new test that measures anything visual gets `@pytest.mark.iphone`. What qualifies and the test that enforces it: `docs/verification.md`.
  - **The e2e phase is diff-proportionate (#568):** byte-compile + the non-e2e pytest suite always run; the *browser* slice is routed against `main` by `scripts/classify_e2e.py` (the scaffold's classifier, byte-verbatim; rules in `.fleet.toml` `[e2e]`, #955): a static-asset-only diff runs Chromium-only smoke, a backend/docs-only diff runs no browser suite, and any `.js`/`.css`/real-page/session-host/e2e-test change (or any mixed/ambiguous diff) runs the full dual-projection suite, narrowed to one declared `[[e2e.surface]]` (Board, Life OS) when every such path sits in it. Uncertainty escalates to full, never narrows; the tier + triggering paths print to console and `webapp/verify-progress.log`.
  - **Gate runtime is a property of this host: re-measure before trusting any figure** (#1512, #1515). Worker counts: `$UnitDefaultWorkers` (override `UNIT_WORKERS`) and `$E2EDefaultWorkers` (override `E2E_WORKERS`; `1` = serial) in `scripts/e2e-gate-route.ps1`. Keep the disposable webapp scoped to the launch target (`pin_launch_target`, #1512). Tests marked `serial` run after the workers. Progress goes to gitignored `webapp/verify-progress.log` (lines tagged `[gw1]`); on a run that looks wedged, every `START` without a matching `DONE` is a test still in flight — read them all before killing anything.
- **Restart and verify before hand-off** — procedure: [`docs/restart-and-liveness.md`](docs/restart-and-liveness.md). Recipe: after the gate passes (unless I said not to), `tray.bat --restart` (reclaims `:8445`, preserves `:8446`), then a bounded poll of `GET /api/version` until `git_sha` matches `HEAD`. A session-host-path change is not live until `:8446` restarts: gate on `session_host.stale_relevant` (`true` → report "merged, not yet live"), and never restart `:8446` as a side effect of finishing an issue.

## session-host
- what/why: the `:8446` session-host (`app/webapp/session_host/`, `app/__init__.py`, `app/webapp/__init__.py`, `src/__init__.py`, `src/agents.py`, `src/app_config.py`, `src/audit.py`, `src/build_info.py`, `src/chief_session_end.py`, `src/diagnostics.py`, `src/env_path.py`, `src/runtime_files.py`, `src/session_host.py`, `src/session_host_composer.py`, `src/session_host_input.py`, `src/session_host_scan.py`, `src/session_hosting/`, `src/subprocess_flags.py`, `src/vt_snapshot.py`) hosts the user's live Coding/PTY sessions. Spawned detached from the tray subtree (`cmd /c start`, re-parented per project-scaffolding#35) so a `taskkill /T` subtree kill can't reach it, and the fresh tray re-adopts it; deliberately excluded from `tray.bat --restart`'s port-reclaim sweep to protect those live sessions (#611/#615).
- path list: that list is the session-host server module's **first-party import closure** — `src.session_host_paths.session_host_import_closure()` computes it statically from the import graph and `tests/unit/session_host/test_session_host_paths.py` fails when the declaration drifts from it (#923). Add the module here in the same PR that makes the session-host import it — the test tells you. Out of scope: the argparse bootstrap above the server module (launcher.py → the CLI dispatcher). Deliberately *kept off* the closure: `src/console_input.py` (#967), which `RemoteSession.submit_input` runs as a fresh `python -m` subprocess per message — a fix there is live on the next send without a `:8446` restart.
- update command: `scripts/restart-session-host.ps1 -Confirm` (confirmation-gated, manual/operator-only — kills every live PTY including a standing fleet chief; never wired into a normal ship flow; bare, without `-Confirm`, it exits 1 and does nothing). Wraps `tray_lifecycle.ps1 reclaim -Ports 8446`, then `tray.bat --restart`, then polls `/api/version` until `session_host.stale_relevant` is `false`.
- liveness signal: `GET /api/version`'s `session_host.stale_relevant` (raw sha-diff fact lives in `session_host.stale`; `stale_relevant` scopes it to whether a declared path here was actually touched — #635)
- NOT restarted/deployed by: `tray.bat --restart`

## CI expectations
- Workflow `.github/workflows/e2e.yml`, job `verify-before-ship`, on every PR and push to `main`. **Advisory, not required** — the local gate is the contract.
- **CI is the clean-machine half only (#1041): byte-compile plus the non-e2e pytest suite, no browser suite** (`e2e-gate-route.ps1` routes CI to tier `skip`, pinned by `tests/unit/repo/test_verify_gate_route.py`). It covers what a local run cannot: a fresh `.venv` from `requirements.txt` against committed files only. A browser-visible change is proven only by the local gate on this box. The job self-caps at 10 min.

## E2E browser suite — local gate only
Reasoning and examples: [`docs/e2e-conventions.md`](docs/e2e-conventions.md).

- **A timeout in a flaky leg is a flake, not the diff, so rerun once** (PTY input delivery #58, the webkit kill test #286). The real-agent replay pin (#444) is load-sensitive: a red there means check host load. Tunables: `docs/e2e-conventions.md`.
- **Mock non-deterministic boot fetches before `goto()`, don't widen a timeout** (#510).
- **Poll with the fake clock** (`tests/e2e/_fake_clock.py`) and wait on requests (`wait_until`, `flush_requests`); never sleep on a guess (#1376).
- **Assert on a polled-re-render surface** only through auto-retrying `expect()` or `stable_read` / `stable_eval`, never a raw `evaluate()` / `bounding_box()` read (#680, #1346).
- **A test that opens the terminal overlay uses `E2E_OVERLAY_OPEN_MS` (#887), never a literal.**
- **The default Playwright action + navigation timeout is capped at 15s** (`E2E_DEFAULT_TIMEOUT_MS`, #186) so a hang names its locator.
