# Verify app-launcher

Generated by project-scaffolding's `scripts/gen_verify_skill.py` (`docs/verify-skill.md` there). Text between the `gen:begin` / `gen:end` marker comments is regenerated; the `## Gotchas` section and anything outside the markers is yours and survives regeneration.

Start with the feature map: `features/README.md` lists every feature, and each `features/<view>.md` says how a user reaches it and which test drives it. Run the sections in order: Launch, Doctor, Drive, Evidence, Cleanup. Run Cleanup even when an earlier step fails.

<!-- gen:begin launch -->
## Launch

Reach a usable state from an **empty** data directory, on a disposable instance. Never against the live app.

1. **Scratch folder.** Make a fresh empty folder in your session scratchpad. It holds the disposable instance's data and your evidence, and Cleanup removes it.
2. **Isolate the data.** Point `APP_LAUNCHER_DATA_DIR` at that scratch folder before anything boots, so no database or config of the live app is read or written.
3. **Boot** with the repo's own disposable instance, `tests/e2e/conftest.py::_autoboot_server`: the e2e suite's session fixture calls it, so the Drive nodes boot one for you. For a standalone instance, read its signature, call it from a throwaway script in your scratchpad with your scratch folder, and record the PID and port it gives back.
4. **Refuse an occupied port.** The disposable instance must never share the live port (`:8445`). If the port you were given is held, stop and say so; never kill the holder to free it.
5. **Never set `LAUNCHER_E2E_LIVE`.** That is the opt-in that points the suite at the live app. It stays unset, and a guard refusal is a hard stop, never something to bypass.
6. **Ready means** `GET /healthz` on the disposable instance returns 200. Anything else is a failed Launch, not a slow one: read the instance's log in the scratch folder and report it.
7. **Never touch the tray.** Do not run `tray.bat` or restart anything; the live app is not yours to restart.
<!-- gen:end launch -->

## Doctor

Read-only. Report each check as exactly one of `ok`, `stale` or `unknown`. A check that could not be established is `unknown`; never fold it into `ok`. Doctor restarts nothing.

1. **Venv.** `Test-Path .\.venv\Scripts\python.exe` must be true. Invoke Python as `& .\.venv\Scripts\python.exe`; never activate it, never create another.
2. **Browser.** The real test is launching one:
   ```
   & .\.venv\Scripts\python.exe -c "from playwright.sync_api import sync_playwright as p; x = p().start(); x.chromium.launch().close(); x.stop(); print('browser=ok')"
   ```
   A failure that mentions a missing executable means `playwright install chromium` is needed: report it, do not install it unasked.
3. **Disposable port.** The disposable instance must not use the live port (`:8445`). Confirm the boot recipe picks its own free port; if you cannot tell, that is `unknown`.
4. **Live build vs HEAD.** Read-only `GET /api/version` on the live app (`:8445`, loopback), compared with `git rev-parse HEAD`:

```
@'
import json, ssl, subprocess, urllib.request
PORT = 8445
head = subprocess.run(["git", "rev-parse", "HEAD"], capture_output=True, text=True).stdout.strip()
ctx = ssl.create_default_context()
ctx.check_hostname = False
ctx.verify_mode = ssl.CERT_NONE  # loopback only
state = "unknown"
for scheme in ("https", "http"):
    try:
        with urllib.request.urlopen(f"{scheme}://127.0.0.1:{PORT}/api/version", timeout=3, context=ctx) as r:
            sha = str(json.load(r).get("git_sha") or "")
    except Exception:
        continue
    if sha and head:
        state = "ok" if head.startswith(sha) or sha.startswith(head) else "stale"
    break
print("live_version=" + state)
'@ | & .\.venv\Scripts\python.exe -
```

`ok`: same commit. `stale`: different (a squash-merge can change the sha while the content is identical, so diff the content before concluding the wrong code is live). `unknown`: unreachable or no version endpoint. A stale or unknown live app does not block the disposable run; report it.
<!-- gen:end doctor -->

**Live tray (optional, not part of the disposable run).** To see a change against the running instance rather than a disposable one, `tray.bat --restart` (recipe: `docs/restart-and-liveness.md`) then open `https://127.0.0.1:8445` directly; loopback bypasses the bearer gate. Terminal-grade surfaces (Board drawer reply/dispatch, live PTY) also need a WebAuthn passkey unless `webauthn_rp_id` is unset in `config/webapp_config.json`, so the Drive path below (which route-mocks past all of that) is usually less friction for a UI-only check.

**Default: reuse the e2e fixtures, don't hand-roll a browser session.** `tests/e2e/conftest.py` already gives a real Playwright browser against a disposable, auto-booted webapp plus session-host (`app.webapp.server:app`), so a node renders the real changed JS/CSS. Find (or write) the node closest to the surface you touched, then:

1. Run just that node with the autoboot opt-in (see Gotchas): `$env:LAUNCHER_E2E_AUTOBOOT = "1"; .\.venv\Scripts\python.exe -m pytest tests/e2e/<file>::<test> -q --browser chromium --basetemp <scratch>\pytest` (bash: set the variable inline).
2. To see a state, temporarily add `authed_page.screenshot(path=r"<scratch>\x.png")` at the points you want (before/after an action, each theme), always into the scratchpad, then `git checkout -- <test file>` to drop the lines. Never commit them.
3. Toggle theme mid-test with `authed_page.evaluate("document.documentElement.dataset.theme = 'dark'")`; CSS reacts live, no reload.

## Evidence

- Screenshots, traces and logs go to your scratchpad only. Never write them into the repo tree (a public repo must not receive them).
- What goes in a PR: the **node list**, the **pass output** (`N passed`) and one **build line** from the instance you booted: `git_sha` and `built_at` from its `GET /api/version`, next to `git rev-parse --short HEAD`. No images, no real data, no session content.
- State what you did not run and why. Silence is not a pass.

<!-- gen:begin cleanup -->
## Cleanup

Run this last, and also after a failure.

1. Close every browser and browser context you opened.
2. Stop **only** the instance you booted, by the PID and port you recorded at Launch. Never kill by image name (`taskkill /IM`, `Stop-Process -Name`, `pkill python`): other apps and the live tray run the same executables.
3. If the repo vendors `tests/e2e/_browser_sweep.py`, use it to find leaked browsers: it classifies before it kills and reports what it cannot establish as unknown.
4. Remove the scratch folder, then confirm the disposable port is free again.
5. Leave the live app and its tray exactly as you found them.
<!-- gen:end cleanup -->

## Maintain

Keep the feature map true to the source and the live app. Run from the project-scaffolding checkout (`<scaffold>` below), which owns the generator:

1. **Static half.** `& <scaffold>\.venv\Scripts\python.exe <scaffold>\scripts\gen_verify_skill.py --repo <this repo> --check`. The last line is `STATIC=clean`, `STATIC=changed` or `STATIC=blocked` (exit 0 / 1 / 2). It names new `surface()` names not in the map, mapped names whose test is gone, and changed selectors.
2. **Live half.** Launch a disposable instance, then Drive all mapped nodes with `--junitxml <scratch>/maintain.xml`, then Cleanup.
3. **Verdict.** Re-run the check with the evidence: `--check --live-url <base url of the disposable instance> --junit <scratch>/maintain.xml`. The last line is `MAINTAIN=clean`, `MAINTAIN=changed` or `MAINTAIN=blocked`.

- `clean`: the map matches the source **and** the instance answered **and** every mapped node passed.
- `changed`: the map is stale. Fix it in one PR that touches only this skill's files (regenerate, review the diff, fill gotchas). Never edit a test, delete a journey or loosen a selector to make a drive pass.
- `blocked`: boot failed, the app was unreachable, the live guard refused, a Doctor check was `unknown`, the `[verify]` table has a `FILL:` placeholder, or a mapped node is red. A red node is a possible regression for a human to decide on, not map drift. An unreachable app is never `clean`.

## Gotchas

- `LAUNCHER_E2E_AUTOBOOT=1` is required for any ad-hoc `pytest tests/e2e/...` outside `scripts/run-e2e.ps1`. Without it (and without `LAUNCHER_E2E_LIVE=1`) the suite exits with a guard message instead of running, so the Drive command above does nothing until it is set. Never set `LAUNCHER_E2E_LIVE`: that points the suite at the phone-facing webapp.
- The `[verify]` boot is `_autoboot_server`, a pytest session fixture, not a function with a signature: there is no standalone call. Boot by running a node; the fixture picks free ports for both the webapp and a disposable session-host, writes logs to `webapp/e2e-autoboot-*.log`, and stops both at session end. Pass `--basetemp <scratch>\pytest` so its temp config, audit, upload and runtime-data folders land in your scratch folder.
- `--browser webkit` is the iPhone-shaped projection; `chromium` is faster for a quick visual pass. Run both when the diff touches layout/CSS (only `iphone`-marked nodes run on WebKit).
- The suite exports no PID or URL for the instance, and it is gone by the time pytest returns. For the Evidence build line, put a small pytest plugin in your scratchpad (never the tree) with a `pytest_runtest_call` hook that reads the `base_url` fixture from `item.funcargs` and writes `GET {base_url}/api/version` to a file, then load it with `PYTHONPATH=<scratch>` and `-p <plugin>`. Never report the live `:8445` build as the disposable one.
- A full Drive pass ends `N passed, 2 skipped` on Chromium by design (a desktop scrollbar width and an iPhone-only row-tap path; both run under `--browser webkit`). `gen_verify_skill.py --check --junit` counts a skip as `blocked`, so for a Maintain verdict run those two nodes under `--browser webkit` too, or say which skips you accepted.
- `test_settings_sheets.py::test_every_sheet_opens_and_closes` calls `surface()` with a non-literal name, so the generator lists it as not mapped; it is run through its file in the Drive command anyway.
